# 功能测试设计指南

## 覆盖维度

使用以下维度将需求扩展为可测试场景：

| 维度 | 测试内容 |
| --- | --- |
| 功能流程 | 主流程、替代路径、取消/返回/刷新/重试行为 |
| 数据 | 有效数据、无效数据、空值、重复值、已删除记录、过期记录 |
| 边界 | 最小/最大长度、数值限制、日期范围、文件大小/数量/类型限制 |
| 业务规则 | 资格条件、计算、阈值、必需审批、生命周期规则 |
| 状态 | 草稿/已提交/已批准/已拒绝/已过期/已归档及合法流转 |
| 权限 | 匿名/已认证用户、角色、所有权、租户隔离 |
| 集成 | 外部服务成功/失败、延迟响应、部分失败、回调 |
| 错误 | 校验错误、服务端错误、网络错误、超时、重试、恢复 |
| UI 行为 | 按钮禁用、加载状态、确认弹窗、消息提示、导航 |
| 回归 | 可能受新增或变更功能影响的既有行为 |

## 测试用例模板

手工功能测试用例默认使用此表格：

| ID | 优先级 | 场景 | 前置条件 | 步骤 | 测试数据 | 预期结果 | 类型 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| FT-001 | P0 |  |  |  |  |  | 正向 |

优先级参考：

- `P0`：关键路径、收入/合规/安全风险，或发布阻塞项。
- `P1`：重要的常见流程或有业务意义的规则。
- `P2`：边界情况、低频路径或影响较低的校验。

类型示例：

- `正向`
- `反向`
- `边界`
- `权限`
- `状态`
- `错误处理`
- `回归`
- `兼容性`

## 需求分析模式

将需求转换为用例时：

1. 提取参与者、动作、对象、规则、输入、输出和依赖。
2. 列出可观察的验收标准。
3. 按条件和结果拆分每条规则。
4. 为每个可编辑字段添加无效输入和边界输入。
5. 为每个受保护操作添加权限和状态检查。
6. 为每个依赖添加失败行为检查。
7. 为相邻既有行为添加回归检查。

## API 功能测试

针对 API 功能，包含：

- 方法、端点、身份认证、授权和内容类型。
- 必填和选填请求字段。
- 状态码、响应体、响应头和持久化副作用。
- 针对缺失、格式错误、超出范围、重复或未授权输入的校验错误。
- 适用时包含幂等性、分页、筛选、排序和限流。
- 对既有客户端的向后兼容性。

## UI 功能测试

针对 UI 功能，包含：

- 页面初始状态、加载状态、空状态、有数据状态和错误状态。
- 表单校验时机：输入时、失焦时、提交时和服务端响应后。
- 按钮启用/禁用规则和重复提交防护。
- 导航、深链、浏览器前进/后退、刷新和未保存变更处理。
- 仅在影响功能、可见性或任务完成时包含响应式行为。

## 最终回答结构

常规请求返回：

1. 假设
2. 测试用例
3. 问题 / 缺口

大型功能额外添加：

- 范围
- 覆盖地图
- 高风险区域
- 范围外事项
